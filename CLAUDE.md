# Salient — guide for Claude sessions

Salient is a feature-detection lab: a pure C# SIFT implementation (rewritten from the owner's 2019 C++ coursework in `C:\Projects\SIFTDetector`, with its bugs fixed) behind an ASP.NET Core API and a React + MUI UI. OpenCV (OpenCvSharp) is used **only as a reference**: a small "Compare with OpenCV" dialog and reference curves in the robustness bench.

- UI spec: the design mockup "Salient UI" — https://claude.ai/artifact/ELEMEwhtL9FsoABJ34DeDz (Main, Pipeline, Matching, Robustness and Compare artboards).
- Decisions: `docs/adr/0001–0015` (index in `docs/adr/README.md`). Read the relevant ADR before changing architecture; amend it (with a dated note) when you deviate.
- Plan and status: `docs/implementation-plan.md`. All phases 0–9 (milestones M1–M4) are done. There is no CI (ADR-0016): run the checks locally.

## Working rules

- **Never push.** No `git push`, no creating GitHub repos or remotes. Local commits only, until the owner says otherwise.
- **English only** in UI copy, code, comments, docs and commit messages. The owner chats in Russian; reply in Russian.
- Commits use Conventional Commits (`feat(web): …`, `fix: …`) and end with the `Co-Authored-By` trailer.
- Warnings are errors (`Directory.Build.props`: `TreatWarningsAsErrors`, `AnalysisLevel latest-recommended`). Fix analyzer findings properly; suppress only with a justification.
- Package versions are central (`Directory.Packages.props`); don't put versions in csproj files.

## Repository map

| Path | Purpose |
|---|---|
| `src/Salient.Core` | Images (`ImageF`), borders, Gaussian kernels/blur, resampling, SIMD vector ops. No dependencies. |
| `src/Salient.Features` | Algorithm-agnostic contracts: `Keypoint`, `IFeatureDetector` → `DetectionResult`, `KeypointDiagnostics`, `DescriptorSet` (`Real`/`Binary`), parameter attributes (`[Step]`, `[Advanced]`), pipeline observer/artifacts. |
| `src/Salient.Features.Sift` | SIFT: scale space, DoG, extrema, refinement, contrast/edge filters, orientation, heatmaps, descriptor, `SiftDetector`. |
| `src/Salient.Matching` | Brute-force matcher (L2/Hamming), ratio test, cross-check, normalized DLT homography, adaptive RANSAC. |
| `src/Salient.Evaluation` | Image warps, transformations, repeatability/matching metrics, robustness sweeps. May depend on Matching. |
| `src/Salient.Reference.OpenCv` | OpenCV SIFT/ORB/AKAZE adapters; optional at runtime (`OpenCvAvailability`). |
| `src/Salient.Api` | Minimal APIs (`Endpoints.cs`), EF Core + SQLite, Brotli blob store, background run queue (`Runs/`), SignalR `RunsHub`, SkiaSharp codec, layer rendering, samples. Serves the built SPA. |
| `tests/*` | xUnit: Core, Sift (incl. golden tests vs OpenCV), Matching, Evaluation, Api, Architecture (dependency rules from ADR-0002). |
| `benchmarks/Salient.Benchmarks` | BenchmarkDotNet. |
| `web/` | React 19 + Vite + TS (strict) + MUI 9 + MUI X Charts. `src/app` (shell, routes, theme, Zustand workspace), `src/shared` (generated API client, queries, SignalR, canvas viewport, parameter form), `src/features/{detector,pipeline,matching,robustness}`. |
| `web/openapi/Salient.Api.json` | OpenAPI document, generated at API build time and committed. |

Dependency direction (enforced by `Salient.Architecture.Tests`): Core ← Features ← Sift / Matching / Reference.OpenCv ← Evaluation ← Api. Algorithms never reference the API or each other (except Evaluation → Matching).

## Commands

Run the .NET commands from the repo root and the npm commands from `web/`.

```bash
dotnet build Salient.slnx
dotnet test Salient.slnx
dotnet run --project src/Salient.Api --launch-profile http   # http://localhost:5139
npm run dev            # Vite; proxies /api and /hubs to :5139
npm run lint           # ESLint (typescript-eslint strictTypeChecked)
npm run typecheck
npm run format:check
npm test               # Vitest
npm run e2e            # Playwright; needs the API running
npm run screenshots    # regenerates docs/screenshots
npm run api:generate   # regenerate the TS client after API contract changes
docker compose up --build   # production-like container on :8080, data in a volume
```

After changing API contracts: build the API (it rewrites `web/openapi/Salient.Api.json`), run `npm run api:generate`, and commit both. Nothing checks them for drift automatically.

## Invariants (don't break silently)

- **Keypoint conventions:** X/Y are measured from the top-left pixel center, with Y pointing down. `Scale` is σ (OpenCV `size` = 2σ). `Angle` is in degrees, counterclockwise on screen (OpenCV stores `360 − angle`). `Response` is |D(x̂)|. Conversions live in `OpenCvConversions`.
- **Exploration runs** are run with permissive thresholds (`SiftParameters.Permissive()`) plus per-keypoint diagnostics. The UI sliders filter on the client. The extrema prefilter is fixed at `MinContrastThreshold` (0.005), so client filtering equals a strict run exactly. Keep it that way.
- **Cache versioning:** results are cached by a sha256 key. Bump `SiftDetector.Version` when detector output changes, and `RunService.ComparisonVersion` when comparison logic changes.
- **Stage ids** (`SiftStages`, mirrored in `web/src/shared/stages.ts`) are a contract between the backend artifacts and the Pipeline view.
- **SIFT correctness details** (the coursework got these wrong): signed DoG (no abs); contrast test on the [0,1] scale as |D(x̂)|·s ≥ threshold; central differences halved; refinement re-centres on the shifted sample; reject when det ≤ 0; incremental σ blur with a proper kernel size.
- **Every view fits one viewport** (ADR-0015): the shell is `100dvh` and clips its overflow, so a view must fill what is left and shrink its cards instead of growing. `expectFitsViewport` in `web/e2e/helpers.ts` asserts it for each view; mark anything that clips on purpose with `data-clips-by-design`.
- **JSON** uses `JsonNumberHandling.Strict`; otherwise OpenAPI types numbers as `number | string`.

## Gotchas

- **Stop a running `Salient.Api` before building**, because it locks the DLLs.
- Building the API runs the OpenAPI generator (`GetDocument.Insider`). Startup code must not create files or folders in that mode; `BlobStore` creates its root lazily.
- **SkiaSharp, not ImageSharp:** ImageSharp 4.x needs a license key for Release builds, and 3.1.x has high-severity CVEs (ADR-0009).
- **OpenCV runtimes depend on the OS:** Windows uses `OpenCvSharp4.runtime.win`. Linux and Docker use `OpenCvSharp4.official.runtime.linux-x64.slim`, because the full runtime needs GTK/X11 (ADR-0013). The image is about 820 MB.
- Docker networking on the owner's machine is slow (~200 KB/s). The first image build takes 15+ minutes, and the Dockerfile uses BuildKit cache mounts to avoid repeats.
- **PowerShell:** write commit-message files without a BOM (use the Write tool or `UTF8Encoding($false)`) and commit with `git commit -F`. `[IO.File]` resolves relative paths against the process directory, so use absolute paths.
- **TypeScript 6** uses `erasableSyntaxOnly`: no enums and no constructor parameter properties. `openapi-typescript` wants TS 5 as a peer, which is handled by `overrides` in `package.json`.
- **eslint-plugin-react-hooks v7 rules:** no `setState` inside effects (key state by id instead), no reading refs during render, no reassigning variables during render. Fast-refresh files export only components; helpers go into separate modules.
- **Playwright:** navigation items are role `tab`. A collapsed MUI `Collapse` removes its content from the accessibility tree.
- Node 24 LTS (`web/.nvmrc`). Requires the .NET 10 SDK (`global.json`, rollForward `latestFeature`).
